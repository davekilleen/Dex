# Selected vault and pre-tool safety contract

This contract describes Core and the generated portable package. It does not
certify installation, hook trust, or live interception in any host. Test proposals
are data sent to the checker; never run a destructive command to verify refusal.

## One selected vault

`core/context/vault_selection.py` is the shared selector for the native safety
hook, portable session/safety hooks, and the portable read-only MCP tools.

- `DEX_VAULT_PATH`, `VAULT_PATH`, and `CLAUDE_PROJECT_DIR`, when set, bind the
  selected vault. All must resolve to the same existing absolute directory.
  Symlinks to the same directory are equivalent. Relative, missing, and malformed
  selections refuse instead of falling back.
- A request's explicit `vault_path` (or the Core gate's `vault` argument) must
  agree with those bindings. A tool cannot switch a configured session to a
  different vault by supplying another path.
- Without configuration, an explicit selection or one workspace root selects the
  vault. A list of several workspace roots requires an explicit/configured
  selection; the selector never picks the first arbitrarily. The selected root
  must belong to that list. Multiple vaults remain supported by selecting the
  desired root for a session, or explicitly per request in an unbound session.
- A hook's reported working directory must be the selected vault or a descendant.
  File action paths are interpreted relative to that directory. A working
  directory outside the selected vault refuses; it never changes the binding.
- Process cwd is only a last resort when no selection or workspace is provided.
  MCP servers may start in a plugin cache, so configure the selected vault in the
  environment inherited by both the hook and server. A configured server ignores
  its process launch directory. An unconfigured server must start in the vault.

A conflict returns a refusal with no vault contents. Portable MCP tools return
`refused: true` and `code: vault_selection_conflict` as data. Correct the selected
folder and conflicting environment settings, then restart the host/server so both
receive the same binding. This change does not alter the older work server's
context tools or protected mutation services; those require separate contracts.

## Exposed action coverage

Native Claude safety routing includes Bash, Write, Edit, MultiEdit, NotebookEdit,
apply_patch and MCP tools. The portable Claude/Codex matcher covers the same
union. Cursor's preToolUse and Gemini's BeforeTool route all tool names through
the shared checker, including MCP; no claim is made about an unsupported event.

The checker inspects shell command fields and all recognized path fields:
`file_path`, `path`, `notebook_path`, `source`, `destination`, `source_path`, and
`destination_path`. It checks every patch Add/Update/Delete/Move target, including
Codex's `tool_input.command` patch format. It checks symlink-resolved containment.
Patch body text is file content, not an executable command.

Malformed intercepted events, missing required shell/file targets, uninspectable
patches, unknown lifecycle events, and vault conflicts refuse. Unknown tools with
object inputs still have recognized fields checked; an opaque schema is not
understood merely because the hook ran. Claude's native scraper preference stays
in the Claude wrapper and is not promoted into the shared policy.

These checks detect known destructive command patterns and exposed unsafe paths.
They are **not a sandbox or a complete shell-language/MCP policy**: arbitrary
scripts, aliases, indirect paths, unknown server argument names, and tools the
host never intercepts are outside this guarantee. The advisory safety MCP tool
checks only its supplied command/path; the host must honor the result before
acting. Trust-disabled hooks and unsupported hosts have no automatic enforcement.

## Refusal and failure

The native guard and portable Node launcher turn a checker crash, missing helper,
or missing Python runtime into blocking exit 2. Portable Cursor/Gemini structured
refusals use their native deny payloads; successful Claude/Codex refusal uses exit
2 and the existing block payload. No hook can defend against Node/the shell itself
being unavailable or a host ignoring its configured failure policy. Those cases
need real installed-host testing, not a source-only parity claim.

Regression evidence lives in `core/tests/test_harness_safety_parity.py`, existing
safety/package tests, and the native settings-routing tests. Package runtime copies
are generated byte-for-byte; edit canonical Core and rerun the generator.
